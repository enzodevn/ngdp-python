# NGDP API

NGDP V3 begins with a small read-only HTTP boundary. The API reuses the
validated analytical gateway introduced in V2; it does not create a second
data-loading path.

## Current contract

- `GET /health`: process readiness and API contract version.
- `GET /api/v1/energy/summary`: authenticated indicators from the active
  validated snapshot.
- `GET /docs`: interactive OpenAPI documentation generated by FastAPI.

CSV remains the safe default backend. PostgreSQL can be selected through the
existing `NGDP_DATA_BACKEND` environment variable and must pass the same exact
parity gate before its values reach an API response.

## Run locally

From the project root, install the pinned dependencies, create a strong local
token and start the service. In PowerShell:

    python -m pip install -r requirements.txt
    $env:NGDP_API_TOKEN = python -c "import secrets; print(secrets.token_urlsafe(48))"
    python -m uvicorn src.api.app:app --reload

The local API will be available at `http://127.0.0.1:8000`. Interactive
documentation is available at `http://127.0.0.1:8000/docs`. Select
**Authorize** and enter the generated token to test protected operations. The
Swagger interface adds the `Bearer` prefix when it sends the request.

The token exists only in the API process environment. It must contain at least
32 characters and must never be committed. Missing configuration produces a
safe `503` response; missing or invalid credentials produce `401` without
revealing the configured token. Remove the local value after stopping the API:

    Remove-Item Env:NGDP_API_TOKEN

## Delivery boundary

The current authentication is intended for service-level access to the private,
read-only API. User accounts, roles, write endpoints, public hosting and direct
calls to the Statistics Norway API during requests remain outside this delivery.
Those capabilities require separate contracts and security decisions.
